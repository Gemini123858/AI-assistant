## 现状与方向调整

当前 Conversations.context() 将画像、身份配置、完整会话事件及工具结果拼入请求；上下文超限时停止，不压缩。Records.search() 在本地记录表示中执行字符串包含匹配，不检索聊天历史，不具备语义召回。已有资料独立记录、版本和历史快照是可复用基础。

QQ 不宜仅映射成一个永久增长的网页会话。建议复用执行工具，新增长期记忆与上下文选择能力。保存的全部内容、能检索到的内容、单次实际送给模型的内容，是三个不同集合。长期连续性依靠保存和增量整理全部纳入范围的历史，不依靠每轮重发或重读全部历史。

## 参考项目：学什么、保留什么差异

## 内容如何区分

以下为逻辑类别，不代表立即建立七套存储服务。

| 类别 | 保存内容 | 使用方式 |
| --- | --- | --- |
| 原始对话和执行事件 | 谁在何时说了什么、工具调用及结果、来源入口 | 不因压缩改写；按 ID、时间和内容回查 |
| 原始资料 | 邮件、文件、通知原文、网页证据 | 保留独立身份、版本和出处，按需检索和读取 |
| 业务对象与产物 | 通知卡片、任务状态、分析、草稿及发送记录 | 系统记录提供当前状态；历史快照说明当时状态 |
| 用户画像 | 已确认身份、稳定偏好、明确纠正 | 小规模常驻摘要，其余按相关性读取 |
| 近期工作记忆 | 正在讨论什么、具体指代、已选方案、待回答问题、相关资料 ID | 维护当前对话连续性，按话题隔离 |
| 共同经历与助手经历 | 一起讨论或完成过的事情、关键决定、实际任务结果 | 有时间和来源，可跨 QQ 对话召回 |
| 相处经验与表达习惯 | 哪种帮助方式适合用户、双方称呼及共同形成的表达方式 | 短小、可纠正；观察和推断不冒充确定事实 |

“它自己的记忆”至少包含共同经历、实际行动及结果、当前未完事项和经反馈形成的相处经验。助手曾建议某事，只能记作建议；只有用户确认或工具结果才能支持采纳和完成。“我之后提醒你”不是已建立提醒，提醒需要实际调度记录。

伙伴感由连续理解、真实共同经历和合适回应支撑。允许保留有意义的小事、共同用语与当时感受，不以纯任务相关性筛掉一切日常交流。当前情绪先进入近期语境，不从一句话生成永久性格判断；自述情感、推测和客观事件分别标注，不能把生成的日记当作新证据。

## 网页和 QQ 的记忆范围

记忆跟随会话模式和经历归属，不只由当前显示在哪个界面决定。

- 共享：用户身份与已确认偏好、用户选定的资料库、明确的业务记录。
- 网页工作会话：各自的近期对话、工作摘要和资料引用；默认不读取其他会话完整历史，不自动写入 QQ 相处记忆。
- QQ 伙伴会话：持续的近期语境、跨阶段共同经历、相处经验，以及相关的共享画像和资料。QQ 窗口保持连续，不要求频繁手动切话题。
- 网页打开同一个 QQ 会话：仍属于 QQ 伙伴会话，只是展示入口不同。
- 网页成果进入 QQ：通过用户要求或后续确定的共享策略，形成带来源的结果；伙伴可说“看到你保存的结果”，不能说成亲身参与了未参与的交流。

QQ 后台允许存在多个话题状态。新话题不会清空伙伴记忆，也不会把旧话题的全部任务资料常驻。跨话题指代不清时询问，未完任务按自身状态推进，不依赖当前聊天主题。

## 每次请求的上下文如何构建

概念上：本次上下文 = 稳定身份和约束 + 精简画像/相处经验 + 当前工作状态 + 较早对话摘要 + 相关回忆 + 本轮需要的证据 + 最近原始消息 + 当前消息。具体消息排列服从模型 API 的角色和工具调用协议，检索资料不是系统指令。

1. 根据入口身份和会话模式确定可访问范围，读取当前消息、引用对象、最近原始消息和话题状态。
2. 直接引用优先解析到原消息或业务记录 ID；当前正在编辑的草稿、进行中的任务，直接读取最新状态。
3. 从当前消息、最近话题及引用内容构建检索意图。“那个后来怎么样了”需要前文，不能只检索当前几个字。
4. 默认带少量相关经历，支持模型继续搜索历史、记忆和资料。闲聊不为凑上下文注入邮件或工作资料。
5. 资料先返回类型、标题、日期、ID 和匹配片段，选中后取原文或具体段落。回答日期、金额、地址、版本、是否发送等细节时回查依据。
6. 按 token 预算选择内容，预留工具继续调用和最终输出空间。近期原始交流与当前任务约束优先，较远回忆和重复工具输出先退出。
7. 记录本轮加载的记忆 ID、资料版本、摘要检查点及选择原因，以便解释为什么记得或遗漏；不把私人上下文写入公共日志。

预算是可调设计，不预设固定百分比或凭字符声称精确 token 数。沿用现有计数能力并明确兼容服务的估算限制。没有合适记忆时允许为空，不用弱相关内容填满额度。

## 如何找得准

分清两个目标：“想起我们聊过什么”和“找到那份原始材料”。记忆索引优先承接前者；资料和聊天原文索引承接后者，记忆通过 source_refs 连接原文。

先支持 ID、引用、时间、类型、发件人/标题和全文关键词过滤，再建立 BM25 基线。对同义改写、模糊经历描述评估 embedding 召回；有数据证明必要后再加入重排，不先选定特定模型或引入向量数据库。

“上周那封要求补交材料的邮件”先限定时间和邮件类型，再检索补交相关内容。“我们以前是怎么解决这个问题的”先检索经历摘要，再打开关联聊天和任务结果。相似度只代表相关，不代表原文真实、目前有效或已完成任务。找不到时明确当前检索范围，不凭相似回忆补造细节。

## 长期记忆如何更新

- 对话及执行事件先落盘，读取已处理检查点之后的新事件；不用每轮重新读取全部历史。
- 近期工作状态及时更新；较稳定的经历在话题收束、上下文需要压缩或合适批次时整理。重要纠正可以当轮更新，不必等待定时整理。
- 提炼内容与相关旧记忆比对，决定新增、补充、取代或保留冲突；每条记忆保留来源事件、发生时间、范围、状态和修订关系。
- 用户明确纠正优先修正相关派生记忆；用户说过某事、邮件声称某事、助手推断某事必须保留来源区别。新消息不因更晚就自动更可信。
- 本轮结果先用于回复；整理失败可以之后处理同一来源区间，不能把失败区间标为完成，也不能因重跑反复添加同一经历。
- 近期情绪和不确定相处推断不自动升级为稳定画像；用户可查看、纠正、取消某条相处经验。
- “遗忘”优先解释为降低默认召回优先级或标记过时，不因久未访问删除原始证据。不把高频召回当成事实被验证，也不对进行中任务和明确约定使用普通时间衰减。
- 用户要求真正删除时，明确原文、索引、摘要及派生记忆的范围，避免从保留摘要中重新提炼已删除内容；撤销默认召回与彻底删除是不同操作。

## 上下文压缩

压缩用于让当前对话继续，长期记忆提炼用于将来按需回忆，原文归档用于回查；三者分别保存和评估。

使用较早历史摘要 + 最近完整对话，不只保留事实关键词。摘要至少包含当前议题、指代、用户意图、已做决定、待确认事项、真实执行状态、重要原话、交流语气及资料引用，并记录覆盖的事件范围和生成版本。

按完整轮次和工具调用边界压缩，未结束的工具链保留成对消息。不在每次压缩时把所有旧摘要无条件再概括一遍；分段摘要保留来源范围，必要时回读原段修正。原始日志保持可查，摘要与原文冲突时回查原文，业务现态以当前记录为准。

## 举例：一条消息经历的全流程

用户：“前几天那个报名怎么样了？我今天好累，不想再翻邮件。”

近期对话帮助解析“那个报名”；有对应经历则拿到活动和邮件 ID，读取当前通知、草稿及实际发送状态，再按需要读取邮件原文。回复可以自然体谅用户，简短说明还差什么和下一步，而不是先输出一大段检索过程。

更新记忆时分别保存：这次查阅和处理的事实、当前未完状态、用户今天自述疲惫。不能写成“用户一贯讨厌处理邮件”，也不能因曾起草就记成已报名。日后用户问“上次你帮我怎么处理的”，可以从这段经历找到原会话与产物。

## 小步实施与验证

1. 明确内容身份和范围，为原事件、资料、产物与派生记忆建立引用关系；继续 JSON/Markdown，索引可重建。
2. 实现近期原文 + 有来源摘要 + 精确回查，解决单会话上下文增长；保留现有工具执行层。
3. 增加 QQ 经历记忆、相处经验及增量整理；可在真实 QQ 接通前用本地合成对话验证。
4. 对关键词检索的实测缺口加入语义检索，再扩展跨阶段项目经历。是否引入数据库由实际规模和写入需求决定。

用固定多日对话集和带已知答案的检索问题评估：指代承接、经历召回、原文定位、时序/冲突处理、执行状态准确性、跨范围泄漏、压缩前后关键信息保留、调用成本与延迟。检索可用 Recall@K、原文定位成功率；事实回忆检查来源支持，伙伴体验检查语气连贯和是否过度提旧事。

对照当前完整历史基线，分别验证仅压缩、加入经历召回、加入相处经验的效果，不同时替换全部组件。离线流程通过不能证明长期相处体验已达标，需要真实使用反馈。

### 推荐分工

程序负责确定性工作：范围、原文和业务状态读取、token 预算、完整消息/工具边界、ID/版本/来源校验、落盘和检查点。LLM 负责语义工作：话题解释、补充检索、记忆提炼、经历总结、相处经验及冲突含义判断。模型提出的文本有出处不等于语义已经被程序证明。

初版建议“必带的近期上下文 + 少量自动联想 + 主助手自主查找 + 回复后增量整理”。不默认每条消息先调用独立规划模型，也不把所有检索交给主模型自觉触发。后续对复杂指代、旧事追问和跨话题场景，评估增加一次有界的组织调用。

### 回复前：可继续的基础上下文

1. 取短身份配置、画像/相处经验的精简版本、较早历史的有来源摘要，以及最近完整轮次。这里按预算和消息边界选取，不用模型判断是否保留当前句和最近对话。
2. 读取上次维护的工作笔记：当前话题、已决定/未决定的内容、指代候选和关联记录 ID。笔记表示语义理解；任务状态和草稿版本仍从业务记录取最新值。新话题可以由主助手识别，不靠关键词强制分类。
3. 用当前消息、引用消息及最近话题线索查找少量经历候选；时间、实体和业务关联也参与定位。向量是可评估的召回增强，不是必需的前置服务。没有足够相关的结果允许为空，不把“早安/晚安/嗯”永久设为禁止召回——短句可能承接具体经历。
4. 把命中的短记忆、时间、来源 ID 和必要的片段放入本轮，并给出有界的历史目录。相关性通过语义内容和来源判断，重要性与新近性不应让无关记忆挤掉当前任务。避免每轮注入全部旧任务和最近发生的所有事件。
5. 主助手已能理解最近交谈，必要时调用历史/记忆搜索和原文读取。支持改写查询、展开候选或询问歧义；不能因为初次自动召回为空就认定没有旧事。
6. 一轮工具循环内保留已经读取且仍相关的证据，直到完成或明确压缩，不在每次 API 继续请求时独立重选到不同结果、丢失前一步依据。新的读取结果通过标准工具消息加入。

所有旧任务清单只在相关时展开；真正由用户启用的提醒和任务有自己的状态来源，不因没有进入本次 prompt 而停止。程序的规则保证输入边界和连续性，不决定“看到累这个字就必须安慰”之类回应。

### 可选组织调用：限定问题即可终止递归

组织调用不是另一个长期陪伴者。它只接收固定任务说明、当前消息、最近对话、当前工作笔记和一批已检索的记忆目录/片段。输出例如“应该补查的查询”“应读取的候选 ID”“仍存在的指代歧义”，不输出替代全部原始对话的自由文本 prompt，不改助手身份，也不能越过原本的资料范围。

程序提供首批候选，模型在有限资料上做选择。若允许补查，明确辅助调用总预算；它不能再创建自己的组织器。主助手仍可继续查找遗漏，因此组织器不必掌握完整人生记忆才有用。

独立组织器会增加前置延迟，也可能错过关键候选。仅给一个检索 yes/no 不足以证明有收益；应比较查询改写/候选选择是否提高回忆质量。对每轮必跑与按需调用分别评估，不先把额外开销视为必需。主助手使用记忆工具本身也是 LLM 驱动的上下文组织，通常能先复用已有工具循环。

### 回复后：按不同速度维护

| 内容 | 主要触发方式 | 更新职责 |
| --- | --- | --- |
| 原始消息和执行结果 | 每次交互/执行 | 程序记录，不由模型改写 |
| 业务任务状态 | 实际业务执行 | 业务模块更新；模型摘要不覆盖状态 |
| 近期工作笔记 | 有实质变化的轮次结束；继续对话前需要时 | LLM 基于旧笔记和新增轮次提议变更 |
| 经历条目 | 有意义的一段交流、决定或任务结果形成时 | LLM 提炼，挂原文与产物引用 |
| 较早对话摘要 | 近期原文接近预算或形成适合归档的完整段落 | LLM 压缩指定原文范围；保留近期原话 |
| 用户画像 | 明确自述/纠正及时更新；观察逐步归纳 | 明确事实与推断分别处理，关键冲突回查 |
| 相处经验/表达习惯 | 明确反馈及时处理；其余小批量回顾 | LLM 基于真实互动和既有经验归纳，可返回无变更 |
| 核心身份与人格 | 初始配置或用户明确调整 | 稳定配置；不允许普通闲聊或自写日记自动重写 |

“性格成长”可先体现为用语、相处方式、共同习惯和经历的变化，而非每天重写整个人格。助手也可保存有来源的自我反思，例如“上次在用户倾诉时过快提供方案，下次先问是否需要建议”；这是行为经验，不是新的人生事实。

### 维护调用本身的输入输出

同一模型可承担不同调用职责，不需独立 Agent 服务。维护调用输入限定为：维护规则、尚未处理的新原文区间/执行事件、旧工作笔记、相关旧记忆及必要的源记录。能看见旧内容只为比较，不再次把旧摘要当新增证据。

候选操作可包含 add（新建）、revise（修订）、supersede（取代）、no_change（不变）；附目标 ID、内容、来源事件 ID，以及事实/推断或适用范围。程序核对来源存在、目标版本和允许修改的范围后提交。普通来源存在校验不能证明文本被原文支持，内容错误仍需通过来源回查、用户纠正和抽样评估发现。

先从新交流提炼候选，再定向读取相关旧条目处理冲突；不把整个记忆库反复交给模型全量重写。精确重复由程序处理，语义重复/冲突由模型判断。只允许基于实际新增来源形成新支持，不因为一个说法在摘要、日记和回忆中被重复转述就提高可信度。

工作笔记需要在下一轮使用前尽可能刷新；慢速经验归纳可批量进行，不必阻塞每次回复。维护尚未完成时，新增原文依然在近期窗口内；只对成功处理并保存的事件区间推进检查点。重启后的未处理内容可以重新整理，不自动重放实际业务操作。

### 压缩细则与请求稳定性

分段摘要覆盖明确的事件 ID 区间；当前用户问题、未闭合工具调用和近期交流原文不由组织器任意替换。较远段落可做分层概览，但细节摘要和原始记录仍可展开；若对压缩结果有疑问，应回查原段，不靠不断摘要旧摘要修复。

稳定身份配置尽量保持稳定；当前时间、召回内容、工作状态以明确标注来源的动态上下文提供，不能把外部资料提权为系统指令。普通续轮保留已有消息前缀，工具输出以追加消息参与；确需重建或压缩时再变更上下文。缓存实际收益由具体服务商和请求验证，不照搬第三方项目的命中率或节省比例。

### 首轮实验重点

用同一套记忆库、同一预算、同一批多日对话比较：A（近期+摘要+自动召回）、B（A+主助手检索工具）、C（B+一次组织调用）。分别测显式旧事、隐含联想、短句指代、切话题、错误记忆纠正、检索为空以及压缩后恢复；同时记录无关记忆干扰、来源准确性、延迟与总 token，不预设 C 必然更好。

维护单独比较“仅经历提炼”和“再加入相处经验回顾”，检查错误事实写入、遗漏、错误合并、纠正生效，以及人格和语气是否连续。读写两侧分别定位问题，不能把摘要遗漏、检索未命中和主助手未采用都归为“没有记忆”。

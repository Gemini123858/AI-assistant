# 网页工具交互修复计划

2026-11-03；分支 `fix/browser-interaction`。目标是让模型根据清楚、一致的页面观察完成“搜索、阅读、切换标签、选择配置、核对变化”，减少对网页实现细节的猜测。

设计约束：信任模型的任务判断，优先增加可见信息、准确反馈和可用动作。整理控件只做语义去重，不按文字或场景隐藏入口；正文、链接及候选均保留补读途径。验证页与重试策略提供观测和建议，不新增强制终止次数或域名黑名单。保持现有写入授权、凭据与公网连接边界。

## 已确认的问题

真实网页手工复现使用原 Tasks/JobBrowser，没有调用模型 API：

1. 后台标签事件临时切换全局操作页面，Playwright 回调交错后，一条结果可混合两页的正文、控件和诊断，显式切标签也可能失效。
2. 苹果配置 radio 被关联 label 遮挡；勾选超时后，任务层丢弃原始原因，仅反馈通用交互失败。点击关联 label 可以成功。
3. 控件候选重复且语义不准确，radio 表示成 textbox；200 个元素和大量链接使单条反馈达到数万字符，触发上下文裁剪。
4. 验证页被标为正文可读，模型仍反复重启。未就绪页面同时有拦截记录时，诊断容易暗示拦截就是原因。

旧苹果导航超时的底层原因未确认。后续连续观察已确认一次Bing普通结果最初被站点脚本隐藏、稍后恢复显示；等待过短会只读到导航和页脚，普通结果与顶部总结卡片仍需分别判断。本轮不以放宽权限、统一加长超时或自动重试掩盖问题。私人日志、截图、签名 URL 不提交。

## 本轮实现

| 步骤 | 解法与实现方式 | 验证 |
| --- | --- | --- |
| 1. 页面隔离 | 每个标签持有独立状态；网络/CDP 回调显式使用事件所属页面及其状态，不改当前操作页面。观察绑定当前页，元素记录绑定观察页面。 | 交错回调回归、真实 Chromium 双页后台请求/切换/导航，结果字段一致。 |
| 2. 可恢复的操作反馈 | 归类并脱敏保留遮挡、脱离 DOM、超时等具体原因；错误携带实际操作标签与 URL。checkbox/radio 使用关联可见 label 正常点击并核对最终勾选状态。 | 带遮挡 label 的合成配置页、普通弹窗不穿透、错误工具结果可追溯。 |
| 3. 控件与上下文 | 原生控件提供正确角色及 checked/value；合并关联 label 和可点击祖先的装饰子节点，保留独立事件处理器、无角色/事件委托和 shadow DOM 入口。新增 include_all_elements 完整候选模式，保留原有分页额度；默认正文摘录由60行增至120行，完整正文仍保存、可按行补读。 | 原有无角色卡片流程不退化，配置选项可以识别/选择，记录实际反馈体积。 |
| 4. 页面状态 | 保留 ready 的正文快照语义，增加有证据的验证页标记及换来源/向用户说明的建议；区分拦截观测与根因。工具说明补充恢复策略，避免堆叠场景提示词。 | 验证页合成样例、普通文章含“验证码”不误判、连续反馈与任务结果展示。 |

现有截图工具继续提供按需视觉观察；本轮先完成 DOM 工具的可靠闭环。基于截图的坐标操作单独后续实现，需要验证模型视觉定位、滚动后坐标失效和点击反馈，不与本轮修复混合。

## 验收与边界

先跑相关离线单测与本地 Chromium 流程，再重走公开网页复现。真实网页受时间、网络、验证状态影响；未复现不等于修好，离线通过不等于 Kimi 真实表现达标。由用户在服务器接 API 验收后再决定合并 main。本轮不推送、部署、登录、提交外部事务或解决验证码。

## 本轮结果

步骤1～4首版已实现，等待用户在服务器接 API 验收，尚未合入 main。

- 237项离线单测通过，覆盖交错greenlet回调、CDP会话隔离、错误脱敏、工具反馈传递及正文补读引用。
- 新增 `tests.browser_interaction_smoke` 通过：真实Chromium双页后台请求、切换/导航、无角色卡片、完整候选、关联label勾选、普通覆盖层不穿透。
- 原 `tests.browser_generic_smoke` 与 `tests.browser_conversation_smoke` 通过，涵盖检索、分页、返回、刷新、筛选及统一界面流程。
- 真实网页通过原Tasks执行器重走两轮Bing/研招网切换和文章/目录导航，本轮未再出现字段混合；记录到的4,633次回调未改变当前操作页。Bing一次观察期间自行重定向，被明确报告为需重新观察，没有混合返回旧正文与新页面字段。该计数是有限次诊断记录，不代表线上故障率证明。
- 苹果真实配置页的14英寸radio通过 `check_field` 成功选中，返回checked=true、16英寸=false；没有使用强制点击。默认候选由前轮约1,056个整理为154个（网页本身随时间变化，数量仅作本次对照）。保留194条链接，正文展示更多内容；未承诺单次反馈字符数一定下降。
- 验证页只增加可见状态和恢复建议，不自动终止任务、不新增域名或重试次数限制。访问权限、调用预算和导航等待时间没有放宽。尚未加入坐标点击工具。

真实网页与原始模型上下文、事件日志保存在私人忽略目录，不纳入提交。真实Kimi行为仍须用户验收；旧导航超时及Bing显示速度差异的具体原因未确认。

## 延迟显示补充

已确认Bing结果DOM最初存在标题和链接，但祖先容器visibility:hidden；项目浏览器一次连续采样在额外等待15秒时仍隐藏、30秒时已显示。旧等待逻辑可能把稳定导航/页脚当作可读快照，链接innerText为空。

本轮补充链接text_source与visible：保留可见文字，缺失时使用aria-label、DOM textContent或title属性；重复URL优先保留有文字的标题节点，并在同级候选中优先可见记录。正文仍只表达可见内容，隐藏标签不混入正文证据。rendering报告文档状态、可见/隐藏文字链接数量，并明确隐藏内容也可能来自普通菜单，不自动判定为加载失败。模型可继续分段wait_page/observe_page，或通过URL打开已观察链接；不强制显示、不统一等待30秒、不增加站点例外或停止规则。空h1回退document.title，避免丢失页面标题。

验证覆盖隐藏标题恢复、普通折叠菜单不阻塞、重复URL标签择优、属性标签来源，以及元数据从存储传入模型和按行补读。238项离线测试、扩展后的交互Chromium流程及原通用浏览流程通过；延迟显示样例中，隐藏标题可读且明确标记，分段等待后转为可见正文，普通折叠菜单不会阻止返回。

真实Bing原执行器回查也通过：隐藏阶段返回实际结果标题、text_source=dom_text、visible=false；分段wait后更新为visible_text、visible=true，普通结果正文可读取。该验证未调用模型API，不证明顶部总结卡片一定出现，也不证明模型每次都会选择合适的等待策略。

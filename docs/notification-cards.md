# 通知卡片与导入资料

2026-10-30，首版已实现，离线流程通过，待用户真实 API 验收。继续在 `feat/unified-assistant` 开发，验收前不合并 main。

## 对象与命名

- 当前 `notification` 实际是导入原文及其分析，不是一条独立事项。新界面和工具改称“导入文本”，统一资料类型为 `text`；原 messages 文件仍保存原文与分析，无需改文件身份或批量迁移。
- 新增 `notice` 表示独立通知卡片，一卡一事，拥有 ID、版本、标题、说明、建议行动、开始／结束／截止时间、待确认信息、来源和修改历史。
- 来源引用邮件、导入文本或网页任务的记录 ID，可补充已保存网页的 page_id、URL 和逐字依据。通知可无来源手工创建，也可有多个来源。
- 旧会话中的 notification 引用只在读取边界识别为导入文本，不重写历史，不让旧名称占用新通知的含义。

## 用户流程

左侧“通知”打开卡片面板，提供近期／全部／已过期／时间待确认／已删除、搜索、新建、编辑、删除、恢复和加入当前对话。聊天仍只有主入口；从面板加入通知后返回原会话，保留已输入文字。

“导入文本”在资料管理和聊天旁均可进入，支持粘贴正文或上传 txt/md 文本，JSON 批量导入继续保留。导入只保存，不自动调用模型。

邮件／文本的已有分析事项提供“保存为通知”；文本分析整体可以创建一张卡片。网页结果也可保存为通知，再由用户编辑时间等信息。聊天可直接要求分析并调用创建通知工具，无需分两轮。

卡片时间允许留空、仅日期或带时区精确时间；不补出未知时分。开始／结束／截止分别维护。修改卡片可以纠正原分析，不改写来源原文；保留原依据，历史记录是谁修改了什么。重新分析来源不自动覆盖或重建卡片。

## 实现与操作约定

JSON 存入 notices 目录，复用 Store 的锁及原子写入；一份文件包含当前对象和递增版本历史。手工与模型走同一业务方法，修改／删除／恢复均检查版本。删除是可恢复的本地标记，不删除来源；历史会话快照保留。正常资料搜索排除已删除通知，读取已有引用仍显示删除状态。

复用统一 search_records/read_record；新增 create_notice/update_notice/delete_notice/restore_notice。创建支持一次调用一张卡片，模型可连续创建若干张；先查已有记录，重复保存同一份分析条目返回原卡片，已删除卡片不因此复活。条目按来源与原始内容指纹识别，不按易变化的数组位置识别；显式保存新的分析内容可以创建新卡，不自动覆盖已有手改内容，不承诺语义去重。

资料选择器和会话详情支持通知引用、版本提示、跨会话更新及来源跳转。通知面板和详情共用编辑入口。用户明确要求的本地编辑／删除可以直接执行，目标不明时先询问。

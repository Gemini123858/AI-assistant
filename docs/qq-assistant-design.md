# QQ 个人助手：初步功能设计

2026-11-04。讨论草案，尚未实现。已确认方向：以 QQ 机器人私聊作为现有个人助手的新入口。以下功能、优先级和交互均为设计建议，不代表用户已授权定时分析、主动推送或外部操作。

当前实施范围已收窄为仅本人文字聊天入口，代码和离线闭环见 [QQ文字聊天入口](qq-chat-setup.md)。本文件其余功能、伙伴记忆与主动协作仍属后续草案，尚未实施。

## 产品目标

在 QQ 联系人中提供一个随时可对话的个人助手：随手提供信息，直接提出任务，持续追问，按约定接收提醒和结果。网页保留资料管理、完整证据、复杂编辑和配置能力；日常任务尽可能在 QQ 内闭环。

首期只面向本人私聊。业务资料可复用；最新规划将QQ作为独立持续交流，网页暂不展示QQ聊天、回忆和便签。接收机器人实际收到的消息，不承诺读取个人 QQ 的其他对话、群历史或特殊转发消息内部内容。

2026-11-04最新讨论调整：用户明确QQ只保留一条持续交流，不提供/new等程序命令；网页暂不显示QQ记录，未来即使展示也只读。主动记忆只有自己的回忆和未完便签，不维护相处习惯。当前设计以 [QQ持续记忆：回忆片段、未完便签与按需工具](companion-memory-plan.md) 为准；此前 [助手记忆、资料与上下文](memory-context-design.md) 保留为研究记录。下文其他未来功能不因此进入实施范围；本轮新记忆策略、命令移除和网页隔离的代码与离线闭环已完成；真实模型与连续回复仍待用户实测。

## 关键场景与交互

### 1. 随手收集，随后处理

用户发一段消息：“先存着，不用分析。”助手保存原文和 QQ 来源，返回短确认与可引用标识。用户之后说“整理刚才那条”，再开始分析。

仅发送资料且意图不清时，短问“要我先保存，还是现在整理？”不因接收自动发起浏览、分析或修改画像。支持用户明确开启“纯资料默认保存”偏好；关闭后恢复询问。普通聊天与导入资料分开，保存聊天历史不等于创建资料。

转发内容按实际可读范围处理：普通文本优先；合并转发、卡片和特殊附件需要实测，不将只收到标题视为已读取全文。

### 2. 从通知到待办和提醒

“这条通知和我有关吗？有关的话整理成卡片，截止前一天提醒。”

助手读取内容，说明相关性和出处，保存卡片；时间明确时回显具体日期、时刻及时区，缺失时询问。提醒是独立记录，与通知关联；修改截止日期时提示是否同步调整提醒。待办区分截止、计划执行和提醒时间，完成后停止相应未触发提醒。每周事项支持单次完成，不能因本周完成而结束整个循环；这一能力需新增。

“提醒我”表示发送提醒，“替我提交”表示业务操作，分别处理。

### 3. 长任务可见、可停、可继续

“帮我找几个符合条件的实习岗位，整理要求和截止时间。”

先返回任务已接收；在阶段变化或需要用户补充时更新，避免把每次工具调用刷进 QQ。完成后先发简短结论、关键结果和来源；长表格或完整证据在网页展开。暂时失败、只覆盖部分来源时明确说明。

“查到哪里了”“停止刚才那个”“只看南京地区”有明确语义。首版执行中修改条件采用停止后重新发起或排队，并告知用户；不承诺实时改变正在运行的浏览任务。取消后保留已完成产物。

### 4. 邮件在 QQ 中处理

查看已同步邮件、筛选、分析、起草及修改均可复用。助手展示草稿版本、收件人、主题和正文，支持“第二段改短一点”。首版发送在网页确认。

后续可设计 QQ 内发送确认：展示准确版本和收件人，用户针对该预览确认后发送；草稿变化使旧确认失效。普通“好的”、引用他人的“同意”不能作为发送授权。按当前计划，QQ 内发送审批尚未实现或授权。

### 5. 主动提醒和简报

用户指定时间、频率、资料范围、持续期限和可接受的调用预算后，才创建定时任务。邮件自动同步继续只保存；“每天帮我分析新邮件”属于单独的定时分析订阅。

简报聚合今日安排、即将截止及未完成事项，并支持“第二项明天再提醒”“这件做完了”。默认采用用户确认的免打扰设置，不因未回复持续催促。主动推送受 QQ 平台权限和额度限制，必须实测；失败时在应用中保留投递状态，用户下次聊天可查遗漏。机器人发出或接口成功不代表用户已阅读。

### 6. 有边界的长期委托

“未来两周每天检查一次这个项目的招生页，有新通知时告诉我。”

保存目标页面、关注变化、频率、到期时间和预算；只对约定范围执行。区分内容变化与真正相关的新信息，保留前后证据，避免同一变化重复通知。用户随时可查看、暂停和取消订阅。长期观察不自动扩大到报名、登录或联系他人。

### 7. 围绕项目持续协作

用户可以建立“实习申请”“课程事务”“科研”等项目，把资料、会话、待办和产物关联起来。“继续实习申请”“把这个存到科研项目”选择明确工作范围；无明确归属时只询问或保留在收件箱，不自动给所有对话分类。

科研场景可收集论文链接、实验想法、实验结果和失败记录，按请求形成带来源的阶段回顾。实验数值保留原始出处，推测与观察分开；普通讨论不会自动成为长期画像或已验证结论。这是通用项目资料功能的应用，不新增自动执行研究代码的权限。

## 聊天体验约定

- QQ以自然语言连续交流，不提供/new等程序命令。查看进展、停止等自然语言操作按实际执行能力单独实现，不因移除命令就宣称支持实时打断。
- 一个QQ窗口持续交流；“换个话题”不创建新的用户会话，未完便签可以同时保留，长任务结果明确关联自身任务。
- 引用机器人消息定位对应通知、草稿或任务；不支持平台引用时通过短标识或标题选择，存在歧义就询问。
- QQ内容以简短结论和可操作选项为主，需要时展开；QQ聊天与内部记录保存在本地，网页暂不展示，未来展示也只读。
- 网页与QQ可复用业务数据；网页不进入QQ对话，不通过可编辑会话接口续写QQ轮次。网页自身对话维持原有行为。
- QQ 本身无服务器网页访问能力要求，但网页详情链接需要手机实际能访问部署地址；生成链接不等于解决校内网或远程访问。
- 定时提醒需要服务器持续运行。重启后展示中断与逾期状态，不自动重放外部写操作；具体补发规则在提醒阶段确定。

## 建议实施顺序

### A：QQ 日常入口

基础接入已完成；后续调整为本人绑定、文本问答、持续交流、现有资料/通知/邮件/草稿/网页工具与结果交付，按新规划移除程序命令并隔离网页QQ记录。保留业务资料的网页发送确认。执行中输入与取消按实际能力单独验证，不新增通用调度框架。

验收：在QQ完成“发通知 → 分析 → 保存卡片 → 补查网页 → 追问”，业务产物沿用现有管理，QQ聊天与回忆不进入可编辑网页会话；非本人不能调用私人助手；重启不丢历史。

### B：随手输入和事项闭环

通知截图、语音和 PDF 按一种格式一个闭环逐步加入；待办完成、延期；一次性提醒及明确投递状态。主动提醒先验证平台，再实现复杂规则。

验收：截图抽取的关键字段能核对原图；语音关键时间可纠正；事项能完成/延期；提醒按用户确定的时间尝试投递，失败可查。

### C：主动协作

循环提醒、每日简报、定时邮件分析、网页变化跟踪、任务订阅管理、项目资料与跨会话检索。定期执行仅覆盖用户设置的订阅范围，逐项配置预算。

验收：订阅可查看/暂停/取消；同一变化不重复通知；有免打扰和调用预算；停止订阅后不再触发后续执行。

### D：更多操作在 QQ 闭环

按具体需求增加绑定草稿版本的 QQ 发送确认、文件结果交付和表单预览/提交审批。每项独立设计与验收，不以“接入 QQ”默认扩大权限。

## 技术落点与待验证事项

候选路线：薄 Node.js 程序复用腾讯 QQ SDK 与扫码连接包，通过本机鉴权接口调用现有 Python 应用；Python 仍为业务记录唯一写入方。复用 Conversations 的轮次/事件和 Records 的资料引用，不引入第二套模型工具循环。

账号实际绑定、本人身份映射、长任务回复窗口、主动消息额度、Markdown/按钮、各种入站媒体及下载能力需要真实验证。SDK 提供的协议能力不能直接视为具体机器人的平台权限。首轮真实联调单独确认账号和消息范围。
